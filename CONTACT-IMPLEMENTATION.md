The redesigned contact page and the enquiry pipeline are implemented in the portfolio repository. The current preview offers WhatsApp and the planner while the website form is disabled. The live site has not been redeployed. Calendly configuration is deferred at Hamid’s request.

## Before the change

- Next.js 16.3.6 exports the App Router pages as static HTML. Vercel hosts the public portfolio. The old contact page offered WhatsApp, a Growth Engine message and the planner. There was no website enquiry endpoint, approved inbox, transactional email configuration or booking calendar in the inspected repository.
- The planner generated a local outline, a text download and an explicitly opened WhatsApp draft. The homepage had a separate local brief download. Both flows are still available.
- The site already had consent-aware GA4 through Google Tag Manager, optional Microsoft Clarity, Ahrefs Analytics and existing project and Growth Engine events. The intro, mobile navigation and transition system were inspected before changing any contact surfaces.
- The existing site uses Manrope, Instrument Serif, charcoal surfaces, warm white type, an orange accent and shared gutters. The original contact and planner were checked at 390px and 1440px. The accessible contact design references were `How Buyers Decide_ From Discovery to Contact.png`, for the connected steps and emphasis, and `portfolio_reference_motion_keyframes.jpg`, for the focal composition and restrained motion.

## Contact and delivery

The contact page pairs an editorial heading with an enquiry panel. A four-step path shows how a project develops from idea to build. The layout uses the site's `--bg` (`#101112`), `--panel` (`#191b1d`), `--text` (`#f0f0ec`), `--line` (`#343739`), `--accent` (`#ff8651`), shared spacing and pill buttons. The first fields come before the process visual on phones. Form confirmation and planner review have a short reveal with reduced-motion support.

The form asks for name, email, service and a short message. Business information, website, budget, timing and partnership details are optional. The planner opens an editable copy of the outline only when the visitor asks to review it. The contact hub, WhatsApp and planner links are available as page content before the form starts.

The static HTML stays in `out/`. A same-origin Vercel Node function handles `POST /api/enquiry/`. It checks origin and content type, limits JSON to 16 KB, validates the payload on the server, checks a honeypot and verifies the challenge with Cloudflare. Redis applies a per-IP limit of 12 attempts per 15 minutes and an overall limit of 60 delivery attempts per hour. The IP and payload hashes are keyed. The Redis receipt expires within 24 hours. The message goes to the approved inbox through Resend as plain text, with the visitor’s validated address as reply-to. [Vercel Node runtime](https://vercel.com/docs/functions/runtimes/node-js) · [Turnstile validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/) · [Upstash REST API](https://upstash.com/docs/redis/features/restapi) · [Resend Send Email](https://resend.com/docs/api-reference/emails/send-email)

A fresh response confirms success only after Resend accepts the message and Redis records the receipt. A repeat with the same reference and details returns the recorded receipt. A repeat after an interrupted provider response uses the same Resend idempotency key and email body. Provider acceptance and arrival in the owner’s inbox are distinct stages. The tests used addresses under `.test` and simulated providers. Inbox arrival remains a release check. [Resend idempotency keys](https://resend.com/docs/dashboard/emails/idempotency-keys)

## Analytics

| Event               | Trigger                                                                                                                    |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `contact_cta_click` | Contextual contact link clicked.                                                                                           |
| `lead_form_start`   | First field interaction or valid autofilled submission attempt.                                                            |
| `form_error`        | Validation or submission failure. The event uses a fixed reason code.                                                      |
| `generate_lead`     | The browser receives a fresh `201` acceptance with the matching receipt.                                                   |
| `contact_click`     | Existing event for WhatsApp and the project story contact link. A WhatsApp call request uses the `discovery_call` context. |

Form events carry the approved source, service category, page path and intent. Failed submissions and receipt replays produce zero conversions. A first acknowledgement lost in transit can therefore undercount accepted leads. Use the inbox as the operational record and GA4 to measure consented conversions. [Google Analytics recommended events](https://support.google.com/analytics/answer/9267735)

After a real approved test submission, verify the event in DebugView or Realtime with consent enabled and mark `generate_lead` as a key event in the correct GA4 property. Verify one event per fresh acceptance and none for validation or WhatsApp clicks. [GA4 key event setup](https://support.google.com/analytics/answer/13128484)

## Account setup for email

1. Approve the receiving inbox and a sender address on a domain or subdomain Hamid controls. Add the sender domain in Resend, apply the SPF and DKIM records exactly as shown in its dashboard and wait for verification. Create a sending-only API key restricted to that domain where the account supports it. Keep the inbound reply mailbox active if the sender address receives replies. [Resend domain verification](https://resend.com/docs/dashboard/domains/introduction)
2. In Cloudflare Turnstile, create a Managed widget for `itshamid.com` and a separate widget for the fixed staging hostname. The form uses the `project_enquiry` action. The server verifies that action and the hostname. [Turnstile widget setup](https://developers.cloudflare.com/turnstile/get-started/)
3. Create an Upstash Redis database for expiring rate counters and receipts. Copy its HTTPS REST URL and read/write REST token. Use distinct databases or credentials for staging and production. Generate 32 random bytes represented as 64 hex characters for `ENQUIRY_HMAC_SECRET`. [Upstash REST API](https://upstash.com/docs/redis/features/restapi)
4. In Vercel **Project Settings → Environment Variables**, add the values from `.env.example` to the intended environment. Set `ENQUIRY_ORIGIN=https://itshamid.com` for production. Set the staging origin to its exact HTTPS origin. Store `TURNSTILE_SECRET_KEY`, `UPSTASH_REDIS_REST_TOKEN`, `ENQUIRY_HMAC_SECRET` and `RESEND_API_KEY` as sensitive variables. Enter the real `ENQUIRY_FROM_EMAIL`, approved `ENQUIRY_TO_EMAIL`, `TURNSTILE_SITE_KEY` and `UPSTASH_REDIS_REST_URL`. Keep the Vercel system environment variables exposed so the function can identify the runtime’s client IP header. [Vercel environment variables](https://vercel.com/docs/environment-variables) · [Vercel request headers](https://vercel.com/docs/headers/request-headers)
5. Set `ENQUIRY_ENABLED=true` first on a private staging deployment. Rebuild so the static form and runtime use the same settings. Verify that the Vercel build includes `/api/enquiry/` and that the existing page URLs, slash behavior and redirects work. Submit from a regular browser to the approved inbox. Confirm inbox placement, reply-to, timestamp, service and reference. Test failure, retry and duplicate protection there. A green Resend activity entry is useful for diagnosing delivery. Check the actual inbox before release.
6. Confirm the privacy notice describes the actual inbox retention, provider settings and contact method. Then enable the production scope, redeploy and repeat the real browser-to-inbox check on `itshamid.com`. Keep the flag off until the staging release checks pass.

## Calendly, when requested

The current call action opens a WhatsApp draft so a visitor can discuss timing directly. The owner can later connect the conflict calendar in Calendly, create a one-on-one discovery event, choose the meeting location or video integration, and approve duration, time zone, weekly availability, notice, buffer and booking limits. Verify a trial booking in two visitor time zones and confirm the invitation, reschedule and cancel links. Then provide the verified public event URL for a lazy embed and an external link fallback. A booking conversion should use a verified provider confirmation.
